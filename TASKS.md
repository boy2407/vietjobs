# TASKS.md — the work board

The one file that says **what is being worked on right now, what comes next, and
what is already done**. [docs/09-lo-trinh.md](docs/09-lo-trinh.md) is the
*strategy* (priorities and why); this file is the *operations* (concrete tasks,
who holds them, what "done" looks like). Written in English (AGENTS.md Rule 6).

**How to use it**

- **Human:** tasks are created, updated and assigned **by the author (Nghĩa)** —
  the author writes the rows, sets *Owner* and moves a task to `doing`. When
  finished, set `done`, fill *Evidence*, and add one line to §5.
- **AI agent (Claude / Cursor / Codex…):** read this file **first** in every
  session, before touching code. §1 is the context you would otherwise have to
  rediscover. Work only on the task the author assigned; do not create, reassign
  or re-scope tasks on your own. Never mark a task `done` without the evidence
  column filled in; never skip a task whose dependency is still open. After any
  real change, update that task's row and §5 in the same session. A section may be
  split out to `tasks/T<n>-<slug>.md` (Rule 7 in §3); the pointer here says so.

Status vocabulary: `todo` · `doing` · `blocked (why)` · `done` · `dropped (why)`.

### T8 — recurrent head: Bi-GRU + Bi-LSTM + CNN over PhoBERT tokens (upgrade of the dense head)

Architecture from Tran et al. 2021 (arXiv:2112.11052, `2112.11052.pdf` in the repo root; originally Huynh et al.): input → embedding → SpatialDropout → two parallel branches (Bi-GRU → Conv1D, Bi-LSTM → Conv1D) → avg-pool + max-pool of each → concatenate → dense. Adapted here: the "embedding layer" is **frozen PhoBERT token states** `[n, 256, 768]` (not pooled `[n, 768]`), the output is our 16-class softmax for `category` and the `log1p` Huber head for `salary` (the paper is multi-label with sigmoid). Note: in the paper this model scored **below** multilingual BERT — the question T8 answers is whether it beats *our* frozen dense head (`dl-cat-s2` 0.6025, `dl-sal-s2` MAE 4.15tr), not fine-tuning.
